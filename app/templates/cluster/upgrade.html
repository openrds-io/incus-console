Every member of a cluster runs the same version of Incus. Once one member is upgraded, it waits, blocked, until all the others are too: in that time the cluster takes no changes, but the instances keep running. So upgrade the members one after another without stopping in between, in the order below. The console reaches the cluster through the last one.

There is no need to evacuate a member for an Incus upgrade. Evacuate it (on its own page) before you restart the machine itself, for a new kernel or work on the hardware.
