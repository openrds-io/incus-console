The console checks every request against the user's role. On a remote server each user also has a certificate of their own, which keeps them inside their projects whatever the console does. Inside a project, though, Incus cannot tell a Viewer from a Project admin: only the console can.

Roles enforced by Incus closes that gap. The console writes a small program (an authorization scriptlet) to the server, and Incus runs it for every request made with a restricted certificate. A Viewer's change is then refused by Incus itself.

What changes on the server

  • Two server settings: authorization.scriptlet, and authorization.client.tls-restricted set to scriptlet.
  • Restricted certificates the console did not issue keep working as before, inside the projects they list. The scriptlet takes over that check from Incus.
  • The console's own certificate, other unrestricted certificates and the server's local socket are not affected.
  • The console rewrites the scriptlet whenever users, groups or roles change.

If it ever misbehaves, on the server: incus config unset authorization.client.tls-restricted, then turn it off here.
